# ② 整理现有库

用户说「刮削不出来」「TV 端识别不了」「按 TMDB 改名」「集号对不上」时走这条。

目标：**把已有文件理成正确结构 + 规范名字**，不追求搬运量最小，只追求结果与 TMDB 一致。

## 第 1 步 · 取库内现状

**逐层展开**，不要只看顶层。

- **确认工具返回的「预览」不是全量。** 列出目录的接口常只回一个受限的预览条数（实测封顶 5 条），真正的全量落在**落盘产物**里。**核实目录内容一律读落盘产物**，`count` 才是可信条数。
- 只传完整的目录 FID。**只给后缀、不给前缀会静默返回空结果**，看起来像「目录是空的」。

## 第 2 步 · 取 TMDB 权威口径

见 [tmdb-data.md](tmdb-data.md)。要拿到：**每季的集数、每集的集号与标题**。

## 第 3 步 · 比对，把差异摊开

用 `scripts/gen-rename-plan.mjs --dry-run` 或 `scan-coverage.mjs` 得到：

- 每季**文件数 vs TMDB 集数**（不等就是差异点）
- 覆盖到的集号、缺号、**越界集号**（库里有但 TMDB 该季没有）
- 标题不符的条目

⚠️ **差异有两种，处理方式完全不同**：

| 类型 | 例子 | 处置 |
|---|---|---|
| **编号对但顺序错**（如相邻两集标题互换） | 库里 E07/E08 的标题与 TMDB 相反 | 必须定案谁对，按标题重排 |
| **集号口径不同**（总数都不等） | 库里季节 31 集、TMDB 42 集 | **让用户选口径**，别自作主张 |

**先给用户一张逐季对照表**，再动手。

## 第 4 步 · 结构判断（比改名更容易错）

先判断库属于下面哪种情况，**情况不同做法差很多**：

### 4.1 只是名字不对 → 全原地改名，不建任何目录

若「剧目录名 + 季目录名 + 文件名」层级已经正确、只有名字不对，就用**原地改名**（`to` = 原父目录）。不产生空目录，也就不用事后收拾 —— **能省掉一堆麻烦，先判断是不是这种**。

### 4.2 同一部剧散落在多个目录 → 必须合并

中文名目录与原名目录常是同一部剧。不合并的话库里会有两份，刮削只能命中一个。
做法：把新季目录**改名 + 移动到已有剧目录下**（**复用目录，不新建**）；文件的父目录不变、只需原地改名，这是最省事的一步到位法。

### 4.3 双层同期嵌套 → 压平

形如 `剧名 Season 1/剧名 Season 1/*.mp4` 时，直接取**内层**目录改名为 `Season 01` 并移动（带着内容走），比新建目录再搬文件少一层空壳。

### 4.4 跨季绝对集号 → 先验证再切分

集合形如 `CE001…CE208` 时，先验证它是不是 TMDB 的跨季连续集号（用几个锚点对撞，如 `CE122` 是否等于 `S03E18`），确认后按季边界切分。**别按目录名信。**

### 4.5 特辑混在正季里 → 用时长/体积筛异常值

正片 7 分钟、某集 28 分钟 ⇒ 大概率是特辑，应进 `Season 00`，且正季的后续集号会**顺位前移**。
**用元数据里的时长/体积做异常值筛查，比看文件名可靠。**

### 4.6 子集合可能是独立剧

迷你短片、跨剧联动在 TMDB 常是**独立条目**，不要硬塞进母剧的某一季。

## 第 5 步 · 生成方案并执行

方案是「新建目录（如需）+ 移动 + 改名」的结构化声明。通用形态：

```json
{
  "version": 4,
  "new_folders": [{"plan_id": "s_b00", "parent_fid": "<父目录FID>", "path": "Season 00"}],
  "operations": [{
    "op": "move",
    "to": "<目标目录FID | 已声明的 plan_id>",
    "items": [{"fid": "...", "parent_fid": "...", "origin_name": "...", "new_name": "..."}]
  }]
}
```

要点：

- `parent_fid` / `origin_name` **每项必填**，缺一即整批被拒（服务端三元组校验）。
- `to` 可以用本批声明的 `plan_id`（把文件放进新建目录）。
- 先 `check`（拿指纹）再 `apply`（带上指纹）。`check` 与 `apply` 都要**显式带任务目录参数**，工具不会「自动沿用最近一次」。

### ⚠️ 字符集校验比你想的严

批量整理的校验器通常**只报第一个错**，后面藏着的看不见 —— **别靠一遍遍试工具**。

- **半角逗号 `,` 和百分号 `%` 也是非法字符**（很多人只盯着路径分隔符 `\ / :` 而漏掉）。
- 校验对象**同时包括原文件名**，而原文件名是云端现状、**不能改写** → 先确认它是否合法，不合法就得先单独做一次预清洗改名。
- **对策**：本地把校验规则 1:1 复刻成一个小校验器，跑到全绿再交接口。`scripts/gen-rename-plan.mjs` 已内建。

## 第 6 步 · 回读验证（必做）

重新列目录断言：

- 每个季目录的**条数**与 TMDB 集数一致（或差异已解释）；
- 文件名全部符合 `^剧名 - SxxEyy - `；
- 集号无重复、无空洞（若 TMDB 自身有空洞见 [pitfalls.md](pitfalls.md)）；
- **旧的中转/空壳目录 0 残留**。

## 坑速查

| 坑 | 症状 | 处置 |
|---|---|---|
| 任务目录已冻结到上一轮方案 | 新方案 apply 报「冻结方案指纹不符」 | **新一轮独立整理要重新初始化**拿新任务目录 |
| 把文件记录的父目录字段当目录 FID | 操作项数量暴涨到「文件数 + 1」 | 目录 FID 必须取自「列父目录」返回的**目录记录** |
| 同一目录下计划目录名重复 | 方案被拒 | 计划名唯一 |
| 遍历清单末行漏读 | 末尾目录没处理到 | 每轮单独补跑一次末尾项 |
